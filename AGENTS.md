# Подход Бот: инструкции для работы в репозитории

## Назначение и устройство

Небольшой Telegram-бот на aiogram 3. Считает объёмы пива из сообщений
`#подход #имя 0,5л комментарий`, хранит их в PostgreSQL и формирует `/stats`.
Сохранять простоту: не добавлять фреймворки и слои без конкретной необходимости.

Структура и настройка — в `README.md`, цикл разработки — в
`docs/development.md`, отложенные решения — в `docs/roadmap.md`.

## Правила изменений

- Сначала смотреть `git status` и diff: сохранять изменения пользователя.
- Поддерживать Python 3.9+ (текущий `venv` — Python 3.9).
- Сохранять стиль персонажа и язык ответов. Не менять его молча при замене API.
- Оба вида статистики используют один `StatsLLM.generate`; не дублировать запросы.
- Не выполнять синхронные сетевые LLM-вызовы в обработчиках aiogram.
- Промпты не должны зависеть от поставщика. Специфические поля API — в адаптере.
- Для совместимого Chat Completions API менять конфигурацию. Для другого
  протокола реализовать `ChatClient.complete` и подключить клиент в `main.py`.
- Числовой отчёт считать по БД; ошибка LLM не должна мешать его отправке.
- История подходов — пользовательские данные, передавать её в user-сообщении.
- Не логировать ключи, историю, ответы модели и тела ошибок API.
- Не читать/печатать секреты из `env.json` без необходимости; не коммитить файл.
- Токен тестового бота — в `env.local.json`, также исключённом из Git.
  После ручной проверки остановить бот и БД. Не сохранять токены в документации.
- Не запускать polling и не делать платные API-вызовы для обычной проверки.
- Не менять схему/данные рабочей БД для тестов. `db/schema.sql` не применять
  к существующей БД; отдельного механизма миграций пока нет.
- Пулы, боты, чтение конфигурации — только при запуске, не при импорте модулей.
- При изменении запуска и разбора CLI сохранять совместимость с действующим
  systemd-unit из `docs/development.md`, в том числе с буквальными аргументами
  `>` и `log.log` в `ExecStart`.
- Для каждого диспетчера создавать новые роутеры через `create_router()`.
- Кнопки статистики доступны всем участникам группы; отчёт публикуется новым
  сообщением, исходное меню не редактируется. Подтверждать callback до вызова LLM.

## Проверка

- Быстрый прогон: `venv/bin/python -m scripts.check`.
- При изменениях SQL, пула БД, роутеров или сборки отчёта запускать также
  `venv/bin/python -m scripts.check --integration`.
- Быстрые тесты не должны требовать PostgreSQL, ключей или выхода в сеть.
- Интеграционные тесты используют установленную локально PostgreSQL и временный
  кластер. После прогона сервер должен остановиться, данные — удалиться.
  Docker не использовать, отдельную версию PostgreSQL для тестов не устанавливать.
- Приложение не должно импортировать инструменты из `scripts/`. Общие функции
  временной БД для локального запуска и тестов находятся в `scripts/local_db.py`.

Команды ручного запуска и настройки тестового окружения не дублировать здесь:
их источник — `docs/development.md`.
