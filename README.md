# Подход Бот

Telegram-бот на aiogram 3 и PostgreSQL. Регистрирует подходы из текста
или подписи к фотографии: `#подход #миша 0,5л эсса`. Сообщение должно содержать
одного спортсмена. При редактировании сообщения обновляет объём и свой ответ.

- `/stats` — общая статистика и комментарий рефери.
- `/stats миша` — статистика и комментарий по одному спортсмену.
- Отчётный период — 7 дней.

## Запуск

Python 3.9+; требуется существующая PostgreSQL с таблицами `podhods` и
`bot_answers`. Схема и миграции в исходном проекте отсутствуют.

```sh
python3 -m venv venv
venv/bin/python -m pip install -r reqs.txt
cp env.json.example env.json
```

Заполнить `TOKEN`, `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` и `LLM_API_KEY`
в `env.json`. Запускать из корня проекта:

```sh
venv/bin/python main.py
```

`env.json` исключён из Git. Существующий файл при обновлении не перезаписывать.
Старый `MISTRAL_API_KEY` больше не используется. Для DeepSeek нужен отдельный ключ.

## Как устроены LLM-ответы

`/stats` собирает цифры и историю из БД → `StatsLLM.generate` строит сообщения
через `llm_prompts` → `ChatClient.complete` получает ответ от API → обработчик
добавляет комментарий к числовому отчёту и отправляет его в Telegram.

Слой промптов содержит один общий характер и два задания: личный и общий анализ.
Инструкции находятся в system-сообщении, история и цифры — в user-сообщении.
Перенесены пожелания из прежнего локального промпта: малые подходы допустимы,
ответы лаконичные, без Markdown. Повторяющиеся абзацы удалены.

Один экземпляр сервиса передаётся в aiogram через `start_polling(..., llm=llm)`.
HTTP-сессия создаётся и закрывается в `main.py`, переиспользуется между запросами.
Используется уже установленный `aiohttp`; SDK Mistral/OpenAI не нужны.

Сетевые ошибки, таймауты, HTTP-ошибки, пустые, некорректные и оборванные ответы
дают фразу «Комментарий рефери временно недоступен». Цифры при этом отправляются.
Повторных платных запросов автоматически нет. История ограничивается по длине,
сохраняя самые свежие записи; это лимит символов, а не точный подсчёт токенов.

## Настройки и смена модели

Все LLM-параметры можно задать в `env.json` или переменных окружения.
Окружение имеет приоритет для одноимённых параметров. Настройки считываются
при запуске; после изменения нужен перезапуск.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `LLM_ENABLED` | `true` | `false` отключает LLM и загрузку истории для модели |
| `LLM_PROVIDER` | `deepseek` | `deepseek` или `openai-compatible` |
| `LLM_BASE_URL` | `https://api.deepseek.com` | Базовый URL API, без `/chat/completions` |
| `LLM_MODEL` | `deepseek-flash` | Идентификатор модели |
| `LLM_API_KEY` | пусто | Ключ выбранного сервиса |
| `LLM_TEMPERATURE` | `0.85` | Температура генерации, 0–2 |
| `LLM_MAX_TOKENS` | `1000` | Максимум токенов ответа |
| `LLM_TIMEOUT_SECONDS` | `45` | Общий таймаут запроса |
| `LLM_MAX_HISTORY_CHARS` | `24000` | Максимум символов истории |

Для DeepSeek также принимается `DEEPSEEK_API_KEY`, если `LLM_API_KEY` пуст.
При отсутствии ключа бот продолжает выдавать числовую статистику.

По [документации DeepSeek](https://api-docs.deepseek.com/) на 21.10.2026
используется `deepseek-flash` и совместимый с OpenAI Chat Completions API.
Для коротких комментариев адаптер DeepSeek передаёт `thinking.type=disabled`.

Для другого совместимого сервиса задать:

```json
{
  "LLM_PROVIDER": "openai-compatible",
  "LLM_BASE_URL": "https://your-provider.example/v1",
  "LLM_MODEL": "your-model-id",
  "LLM_API_KEY": "your-provider-key"
}
```

В этом режиме специфическое поле DeepSeek `thinking` не отправляется.
Нужна модель, поддерживающая `system`/`user`, `temperature`, `max_tokens`
и текстовый `choices[0].message.content` в Chat Completions.
Для несовместимого API реализовать асинхронный контракт `ChatClient.complete`
из `app/llm_client.py` и подключить адаптер в `main.py`. Промпты, сервис
и обработчики менять не требуется. Ошибки адаптера должны быть `LLMError`
с безопасным сообщением без секретов и тел запросов/ответов.

## Проверка и оставшиеся ограничения

```sh
venv/bin/python -m unittest discover -s tests -v
venv/bin/python -m compileall -q app routers main.py
git diff --check
```

Тесты проверяют конфигурацию, запрос/ответ API на подменённом транспорте,
два вида отчётов, ошибки, отключение LLM и отправку длинных сообщений.
Не обращаются к реальным сервисам или БД. Живая проверка DeepSeek требует ключа.

Вне LLM остаются особенности исходного проекта:

- Метка «за всё время» использует `get_volume` с глубиной по умолчанию 365 дней.
- В функциях БД используется синхронный psycopg2, несмотря на `async def`;
  запросы БД могут блокировать цикл обработки сообщений.
- Пул БД открывается при импорте, конфигурация Telegram/БД читается из `env.json`
  относительно рабочей директории. Приоритет окружения добавлен только для LLM.
- Регистрация и статистика не ограничиваются текущим чатом.
- Отдельных миграций, запуска в контейнере и конфигурации развёртывания нет.
