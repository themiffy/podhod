# Цикл разработки

Прод: VPS, PostgreSQL 15.8 на том же сервере. Обновление — `git pull`
и ручной перезапуск процесса. GitHub Actions пока не подключены.
Команда перезапуска, расположение логов и версия Python на VPS ещё не зафиксированы.

## Проверки

Быстрые тесты без PostgreSQL, Telegram, LLM-ключей и доступа в интернет:

```sh
venv/bin/python scripts/check.py
```

Проверка с настоящей БД:

```sh
venv/bin/python scripts/check.py --integration
```

Команда находит локальную PostgreSQL в `PATH` или Postgres.app, создаёт временный
кластер в `/tmp` и запускает его только с Unix-сокетом, без TCP. По завершении
останавливает сервер и удаляет временные данные, в том числе при падении тестов.
Существующие серверы и `env.json` не используются. Docker не нужен.

Если бинарники находятся в другом месте, указать их каталог:

```sh
PG_BIN=/path/to/postgresql/bin venv/bin/python scripts/check.py --integration
```

Версия тестового сервера — установленная локально. Каждый сценарий создаёт
отдельную UUID-схему и устанавливает в неё `db/schema.sql`. Telegram и LLM
подменяются на границах API; SQL, обработчики и сериализация сообщений — реальные.
Проверяются регистрация текста/подписи фото, редактирование, связь с ответом бота,
личная/общая статистика, отчётный период, пустая БД, ошибки LLM и откат транзакции.

## Порядок работы

1. Создать ветку, например `codex/edit-approach`, и внести изменение.
2. Добавить проверку поведения и запустить быстрые тесты.
3. При изменении SQL, пула БД или роутеров запустить также `--integration`.
4. Проверить diff и зафиксировать коммит.
5. При изменениях интерфейса пройти ручную проверку тестовым ботом.
6. Обновить VPS до проверенного коммита, при изменении `reqs.txt` установить
   зависимости, перезапустить бот и проверить логи и ответ на `/stats`.

Перед выкладкой записывать предыдущий SHA, чтобы можно было вернуть версию кода.
Когда появятся миграции, порядок отката данных определять отдельно.

## Схема БД

`db/schema.sql` содержит таблицы, последовательности и первичные ключи из
предоставленного дампа, без владельцев и создания/удаления БД. Применять только
к новой пустой БД. На рабочем VPS повторно выполнять этот файл не нужно.
Будущие изменения структуры оформлять отдельными нумерованными миграциями.

## Ручная проверка Telegram

Использовать отдельного бота и чат с отдельной БД и конфигурацией:

1. Отправить `#подход #миша 0,5л`, проверить ответ и подпись фотографии.
2. Изменить объём, проверить обновление ответа и цифры в `/stats`.
3. При изменении промпта оценить один личный и один общий ответ.

Автоматические тесты проверяют содержимое Telegram-запросов, но не отображение
в клиентах Telegram, права бота и доступность внешних сервисов. Inline-кнопок
пока нет; при добавлении проверять клавиатуру и обработку callback в тестах,
а отображение и реальное нажатие — вручную.
